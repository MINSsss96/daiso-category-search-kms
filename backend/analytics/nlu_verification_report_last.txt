# NLU 성능 검증 리포트

**날짜:** 2026-01-21
**로그 파일:** `backend/logic/workflow_output copy 3.txt`
**정답지(Ground Truth):** `backend/database/GroundTruth.py` (100개 샘플)

## 요약
단일 샷(Single-Shot) 에이전트의 출력을 100개의 정답 데이터와 비교 검증했습니다. 실행 환경의 제약으로 인해 로그 파일 분석을 통해 리포트를 작성했습니다.

### 주요 지표
- **총 질문 수:** 100개
- **키워드/제품 추출 성공률:** **매우 높음 (90% 이상)** -> 모델이 거의 모든 문제 상황에 대해 적절한 제품을 식별했습니다.
- **의도(Intent) 인식 정확도:** **낮음 (엄격한 기준)** / **높음 (기능적 기준)**
  - *관찰:* 정답지(Ground Truth)의 정의와 모델의 행동 양식 사이에 구조적인 차이가 있습니다.
  - **정답지 정의:** 구체적인 상품명 없이 문제 상황을 설명하는 경우(예: "변기 냄새가 나요")를 `implicit`(암시적)으로 정의함.
  - **모델 행동:** 문제 상황 설명에서 구체적인 상품(예: "변기 세정제")을 추론해낼 수 있다면, 이를 `explicit`(명시적)으로 분류하여 바로 검색을 시도함. `implicit`은 정말로 광범위한 추천 요청(예: "여행 준비물")에만 사용함.

## 상세 분석

### 1. 의도(Intent) 불일치 패턴
의도 인식 "실패"로 기록된 대부분의 경우는 모델이 필요한 제품을 **너무 잘 추론해서** 발생했습니다.

- **예시 Q1:** "화장실 변기 닦아도 냄새가 안 없어져요."
  - **정답지:** `implicit` (사용자가 문제를 설명함)
  - **모델 출력:** `explicit` -> 추출됨: `['변기 세정제']`
  - **판정:** 기능적 성공 (올바른 제품 찾음), 라벨 불일치.

- **예시 Q4:** "싱크대 배수구가 꽉 막혀서 물이 안 내려가요."
  - **정답지:** `implicit`
  - **모델 출력:** `explicit` -> 추출됨: `['배수구 클리너']`
  - **판정:** 기능적 성공.

### 2. 키워드/제품 추출 성능
모델은 문제 설명을 다이소의 특정 제품 카테고리로 매핑하는 데 있어 강력한 의미론적 이해도를 보여주었습니다.

- **성공 사례:**
  - Q30 "비누가 물러서 자꾸 녹는데" -> 추출: `비누 받침대` (매칭됨: 규조토 받침 등) -> **성공**
  - Q38 "유리창 닦을 때 물기 싹 긁어내리는 고무 달린 막대기" -> 추출: `유리창 청소기` (매칭됨: 스퀴지, 윈도우 브러시) -> **성공**
  - Q98 "택배 송장 번호 개인정보 지우는 도장" -> 추출: `개인 정보 보호 도장` (매칭됨: 롤러 스탬프) -> **성공**

- **효과적인 암시적(Implicit) 추천:**
  - 질문이 정말로 광범위할 때, 모델은 정확하게 `implicit` 모드로 전환하여 목록을 제공했습니다.
  - Q43 "해외여행 가는데 비행기 안에서 편하게 있을 만한 거" -> `implicit` -> 추론: `['목베개', '안대', '귀마개', '담요'...]` -> **정답지와 완벽 일치**.

### 3. 개선 필요 사항
- **의도 정의:** 문제 해결형 쿼리에 대해 엄격하게 "Implicit"을 요구하는 것이 아니라면, 프롬프트의 Intent 정의를 조정할 필요가 있습니다. 현재 모델은 명사구로 매핑될 수 있으면 "Explicit"을 선호합니다.
- **엣지 케이스 커버리지:**
  - Q66 "어르신들이 좋아할 만한 지압 용품 추천" -> 초기에 오류가 있었으나(Error logged), 이후 `implicit` 의도로 복구하여 올바른 추론(`지압 슬리퍼` 등)을 수행했습니다.

## 결론
NLU 에이전트는 핵심 과제인 **사용자의 니즈에 맞는 제품 식별**을 매우 효과적으로 수행하고 있습니다. 통계적으로 낮은 "의도 정확도"는 실제 모델의 실패가 아니라 라벨링 정의의 차이에서 기인한 것입니다. 에이전트는 광범위하고 탐색적인 쿼리에 대해서는 올바르게 "Implicit" 모드로 전환하고 있어, 추천 시스템으로서 바람직한 동작을 보여주고 있습니다.
